# Changelog

All notable **user-facing changes** to Kaiwen Gateway are recorded in this file.

This project follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and intends to use [Semantic Versioning](https://semver.org/spec/v2.0.0.html) for its Python distribution. The **Python package version**, any **external Gateway wire/API protocol version**, and **provider adapter compatibility** are separate concerns; a package release does not automatically change a wire protocol version.

> **Project status (2026-11-09): Pre-alpha implementation.** The repository contains an implemented pre-alpha core architecture, ASGI server, synthetic telephony/media transports, Voice audio bridge, telemetry foundation, and process-isolated synthetic load harness. The intended first alpha release is `0.1.0a1`, but **no package has been published to PyPI, no release or version tag has been created, and no production readiness, live Verimor interoperability, or external AI provider integration is claimed**. Items under **Unreleased** reflect unreleased repository development.

### Fixed

- Corrected incomplete retrieval of simultaneously failed Voice Bridge task exceptions in `VoiceBridgeSession._run_supervisor`, preventing unobserved task exception warnings when concurrent pump tasks fail ([PR #28](https://github.com/ImtheKaiwen/kaiwen-gateway/pull/28) / `0dcc82179e08175eab0c43f706b3d67ac2c64035`, verified in GitHub Actions run `42523939041`).
- Introduced deterministic primary-error precedence evaluated in fixed sequence (inbound pump before outbound pump, inner receiver before forwarder) rather than non-deterministic set iteration order.
- Ensured genuine task exceptions strictly supersede unexpected or expected cancellations regardless of task scheduling order, preventing cancellations from masking underlying root-cause errors.
- Improved terminal cleanup safety by attaching a done-callback to the supervisor task, ensuring terminal teardown, buffer drainage, and port closure execute reliably even if the supervisor task is cancelled prior to executing its first coroutine frame.
- Added seven focused regression and adversarial tests verifying concurrent failure handling, error precedence, single-count error metrics, and clean task teardown without resource leaks.
- Bounded Voice Bridge queue insertion on the synthetic path by wiring `synthetic_backpressure_timeout` (default 2.0s) from application state into `VoiceBridgeSession`, preventing unbounded producer waiting when the queue is saturated.
- Protected inbound and outbound EOF sentinel (`_SENTINEL`) queue insertion with `asyncio.timeout(self._backpressure_timeout)`, preventing terminal producer deadlocks when downstream media delivery stalls.
- Introduced a dedicated, validated `send_timeout: float | None = 2.0` on `WebSocketTelephonyMediaAdapter` enforcing write deadlines via `asyncio.timeout` on binary frame and control text socket sends, eliminating indefinite stalls when an outbound frame is sent with an underfilled or empty queue (`outbound_queue_depth=0`). Standalone adapter consumers now receive a finite 2.0-second default (a documented behavior change), while explicit `send_timeout=None` remains available as an intentional opt-in for unbounded waiting.
- Ensured safe adapter teardown after downstream send timeouts by making `WebSocketTelephonyMediaAdapter.close()` unconditionally set `_close_event`, unblock `_outbound_turn_gate`, and wake all turn waiters even if the adapter was previously flagged closed.
- Corrected error classification and telemetry accounting by mapping queue saturation to `VoiceErrorCategory.BACKPRESSURE_OVERFLOW` and downstream send timeouts to `VoiceErrorCategory.PORT_IO_ERROR`, while accurately recording failed downstream delivery attempts in `_unforwarded_outbound_frames` to maintain the frame accounting identity without falsely reporting unforwarded audio as delivered.
- Added 15 regression tests covering queue saturation, EOF timeouts, single-frame downstream send stalls, deadline recovery, explicit close during stalls, adapter close idempotency, cancellation, interruption, and cross-session stall isolation ([PR #30](https://github.com/ImtheKaiwen/kaiwen-gateway/pull/30) / commit `e5c5433d0192f431815a7fe424ff5e6caaa7ade2`, verified on `push -> main` in [GitHub Actions run `42534903921`](https://github.com/ImtheKaiwen/kaiwen-gateway/actions/runs/42534903921)).

## Maintenance policy

This section describes **how to keep the changelog accurate**; it is not a record of released functionality.

1. **Record verified changes only.** Add an entry under `Unreleased` when a meaningful change is completed and supported by the relevant code, documentation, tests, or other reviewable evidence. Do not add promises, speculative features, failed experiments, or unverified provider compatibility.
2. **Write for library consumers and operators.** Describe observable behavior and impact, not every commit, internal refactor, agent prompt, or development step. Prefer concise, specific entries. Link an issue, pull request, or accepted ADR when it materially helps explain a change.
3. **Use the appropriate categories.** The standard headings are `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, and `Security`. Include only headings that have actual entries; do not pre-populate empty sections.
4. **Keep proposed and implemented work distinct.** Documentation-only changes may be recorded as such. An adapter passing synthetic tests is **not** a verified live Verimor integration. A successful alpha is **not** production readiness.
5. **Identify compatibility impact.** Clearly flag breaking changes to the public Python API, CLI, configuration, wire events, authentication, or provider adapter contracts. Explain the migration path in the related release notes when applicable.
6. **Protect sensitive information.** Summarize security fixes without disclosing exploitable details, customer data, credentials, private provider contracts, or incident evidence. Coordinate sensitive disclosures under [`SECURITY.md`](SECURITY.md).
7. **Cut releases deliberately.** Only after authorization and passing the release gate, move the relevant `Unreleased` entries beneath a new `## [version] - YYYY-MM-DD` heading. The date is the actual publication date (ISO 8601), not a planned date. Leave a fresh `Unreleased` section above it. Add Git tag/compare links **only after the corresponding tags exist**.
8. **Do not use changelog entries as acceptance evidence.** Requirement status and acceptance criteria live in [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md); milestones and blockers live in [`ROADMAP.md`](ROADMAP.md); architectural rationale belongs in [`docs/decisions/`](docs/decisions/); coding-agent reporting obligations live in [`AGENTS.md`](AGENTS.md).

### Release format (example only; not an actual release)

The following fenced example illustrates formatting. **It does not declare that a release exists.**

```markdown
## [0.1.0a1] - YYYY-MM-DD

### Added
- <Verified, user-visible capability and its scope.>

### Fixed
- <Verified user-visible defect that was resolved.>
```

Keep this file concise as the project grows; detailed implementation evidence belongs in the associated pull requests, test reports, and release notes.
